# KupuProxy v1.3.3.8

## 🔧 Главное: починено автообновление

Начиная с 1.3.3.3 проверка обновлений в приложении молча не работала. Найдена и устранена
конкретная причина.

**Корневая причина.** Для ограничения размера ответа использовался okio-вызов
`readByteArray(maxBytes + 1)`. Это **точное** чтение: он бросает `EOFException`, если в потоке
меньше байт, чем запрошено. Ответ GitHub API с описанием релиза — это ~3–60 КБ, а лимит стоял
512 КБ, поэтому чтение падало **всегда**. Ошибка гасилась в `runCatching`, и апдейтер приходил к
выводу «обновлений нет».

Тот же баг ломал резервные манифесты, загрузку файла контрольной суммы и загрузку прокси-списков
в `HttpSupport`.

**Исправление.** Добавлен `BoundedRead` (`readAllBounded` / `readUtf8Bounded`): лимит проверяется
через `BufferedSource.request(maxBytes + 1)`, и только затем читается весь ответ. Поведение
покрыто регрессионными тестами.

Затронуто:
- `updater/UpdateChecker.kt` — метаданные релизов (GitHub API + резервные манифесты)
- `updater/ApkDownloader.kt` — файл `.sha256`
- `data/remote/HttpSupport.kt` — загрузка всех прокси-источников

## 🆕 Настоящая фоновая автопроверка

Раньше проверка запускалась только при открытии приложения. Теперь есть
`UpdateCheckWorker` на WorkManager:

- проверка каждые 6 часов при наличии сети;
- уведомление с переходом сразу к установке;
- одно уведомление на версию, без спама;
- переключатель «Автопроверка обновлений» в настройках;
- экспоненциальный backoff при сетевых сбоях.
