# KupuProxy v1.4.0.3

Десктоп-клиент получил встроенные источники прокси и серию исправлений, без которых часть
функций 1.4.0.2 не работала: локальный прокси, выбор файла, автозапуск и системная тема.

## 📦 Встроенные источники (proxy-feeds)

Раньше десктоп после установки был пустым: кнопка «Запустить скан» лишь открывала раздел
«Источники», где нужно было искать файл или URL. Теперь в клиент встроены зеркала из
каталога `proxy-feeds/` репозитория — те же, что GitHub Action обновляет каждые 4 часа:

| Источник                 | Протокол | По умолчанию |
|--------------------------|----------|--------------|
| MTProto · сводный список | MTProto  | включён      |
| SOCKS5 · Kort            | SOCKS5   | включён      |
| SOCKS5 · hookzof         | SOCKS5   | выключен — большой список, берётся случайная выборка из 1500 |

- «Запустить скан» на «Обзоре» и «Быстрый скан» в трее сразу проверяют включённые источники;
- порядок загрузки: **GitHub → jsDelivr CDN → снимок внутри приложения**. Если
  raw.githubusercontent.com заблокирован, срабатывает CDN; если сети нет совсем —
  вшитый при сборке снимок. Откуда взят каждый фид, видно в «Источниках»;
- кнопка «Без загрузки (снимок)» проверяет только вшитый снимок;
- фиды чередуются при склейке, поэтому лимит «максимум за скан» не съедает один источник;
- строки `host:port` без схемы (формат hookzof) теперь разбираются как SOCKS5.

## 🐛 Исправления десктоп-клиента

- **Локальный прокси не пропускал трафик.** Поток «клиент → прокси» запускался только после
  окончания ответа, поэтому запрос не доходил до сервера и туннель висел до таймаута.
  Оба направления теперь работают одновременно.
- **Локальный прокси обслуживал одно соединение за раз** — браузер «висел», пока не закроется
  первая вкладка. Каждое соединение теперь в своём потоке.
- **SOCKS5-туннель почти всегда отклонялся**: в ответе на CONNECT первый байт адреса
  читался как код ответа.
- **WEB-прокси (HTTPS) открывал второе соединение** и отдавал в туннель незащищённый сокет.
  TLS поднимается поверх одного соединения.
- Локальный прокси понимает и обычные HTTP-запросы (`GET http://…`), а не только `CONNECT`,
  и IPv6-адреса `[::1]:443`.
- **«Выбрать файл…» падал**: диалог вызывался через `invokeAndWait` из UI-потока. При отмене
  выбора больше не запускается скан несуществующего `proxies.txt`.
- **Повторный скан во время текущего** запускал второй параллельно — оба писали в один
  список, и список падал на повторяющихся ключах. Теперь предыдущий скан отменяется, а
  кнопки запуска на время скана блокируются.
- Ошибки загрузки файла или URL показываются в интерфейсе, а не только в консоли.
- Полоса прогресса уходила за 100 % («750 / 500»): счётчик первой фазы продолжался во второй.
- **Автозапуск не включался** из установленной версии: путь лаунчера определялся неверно.
  Для uber-jar автозапуск теперь использует `java -jar`, пути с пробелами экранируются.
- «Системная» тема никогда не была тёмной — теперь тема берётся из Windows, macOS и GNOME.
- Окно сбрасывало размер и позицию при обновлении состояния.
- Без системного трея (часть окружений Linux) закрытие окна оставляло невидимый процесс.
- Настройки с не-ASCII символами портились при сохранении; файл теперь пишется атомарно и
  не переписывается на каждый пиксель перетаскивания слайдера.
- График трафика показывает байты в секунду за последние 2 минуты.
- «Открыть в Telegram»: если `tg://` не зарегистрирован, открывается `t.me` в браузере;
  SOCKS5 открывается ссылкой `tg://socks`.

## 🔐 Разбор MTProto-секретов (Android и десктоп)

Секреты в base64/base64url короче 32 символов (например, `7miqLUF…ay5jb20` — fake-TLS
для `vk.com`) отбрасывались как невалидные. Это около четверти сводного списка
`proxy-feeds`: из 561 записи разбиралось 415. Теперь принимаются все, тип секрета и SNI
определяются и для base64.

## ⚙️ Сборка и релиз

- `packageVersion` = `1.4.3`: номер установщика обязан расти, иначе `.msi` не обновит 1.4.0;
- в релиз добавлен запускаемый jar для Windows (`KupuProxy-Desktop-1.4.0.3-windows-x64.jar`);
- коммит манифеста автообновления больше не отклоняется, если в `main` успели прийти
  коммиты зеркала фидов;
- флаг `continue-on-error` для `.msi` теперь действительно применяется.

## ✅ Качество

- 172 unit-теста зелёные: 87 в приложении, 51 в общем модуле (Android и десктоп), 34 в десктоп-клиенте; `lintDebug` без ошибок;
- новые тесты: локальный прокси через настоящие SOCKS5/HTTP-ретрансляторы, параллельные
  соединения, порядок GitHub → CDN → снимок, прогресс скана, версии и пути автозапуска;
- десктоп проверен вручную на Linux: скан встроенных источников — 393 рабочих прокси
  из 653, трафик через локальный прокси выходит с IP выбранного SOCKS5.

## 📦 Сборка

```bash
./gradlew assembleRelease                         # APK
./gradlew :desktop:packageUberJarForCurrentOS     # запускаемый jar
./gradlew :desktop:packageMsi                     # Windows .msi
./gradlew :desktop:packageDeb                     # Linux .deb
./gradlew :desktop:packageDmg                     # macOS .dmg
```

## 🔄 Обновление

APK обновляется обычным автообновлением. Десктоп-клиент — отдельная загрузка.
